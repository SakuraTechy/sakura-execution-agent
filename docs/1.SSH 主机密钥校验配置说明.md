# SSH 主机密钥校验配置说明

## 概述

sakura-execution-agent 在执行 SSH 连接（server_command、server_file_upload）时，默认会校验目标主机的公钥是否在 known_hosts 文件中，以防止中间人攻击。

支持通过 YAML 配置文件或 JVM 系统属性关闭主机密钥校验，但这会失去服务器身份校验保护，
仅用于受控隔离测试环境。网络连通、算法协商和身份认证仍需正常完成，不能把该开关当成通用连接修复手段。

## 配置方式

配置优先级：**显式 JVM 系统属性（-D 参数）> YAML 配置文件 > 默认值**。
配置只在进程启动时加载，修改 YAML 不会让已经运行的 Agent 热更新。

### 方式 1：YAML 配置文件（推荐）

编辑 `conf/agent-config.yml`：

```yaml
# SSH 连接配置
ssh:
  # 是否跳过主机密钥校验
  # true: 跳过服务器身份校验（仅限受控隔离测试环境）
  # false: 强制校验 known_hosts 文件（生产环境推荐）
  skip-host-key-check: false

  # known_hosts 文件路径（当 skip-host-key-check=false 时必须配置）
  known-hosts: conf/known_hosts
```

启动时 Agent 会自动加载该配置文件：

```bash
java -jar sakura-execution-agent.jar
```

如果需要使用其他配置文件路径：

```bash
java -Dsakura.agent.config=/path/to/custom-config.yml -jar sakura-execution-agent.jar
```

### 方式 2：JVM 系统属性（覆盖 YAML 配置）

通过 JVM 系统属性可以覆盖 YAML 配置文件中的设置：

**跳过主机密钥校验：**

```bash
java -Dsakura.agent.ssh-skip-host-key-check=true -jar sakura-execution-agent.jar
```

**强制校验（指定 known_hosts 文件）：**

```bash
java -Dsakura.agent.ssh-skip-host-key-check=false \
     -Dsakura.agent.known-hosts=/etc/sakura/known_hosts \
     -jar sakura-execution-agent.jar
```

### 默认行为（推荐）

如果 YAML 配置文件和 JVM 系统属性都未设置，默认行为是：

- `skip-host-key-check: false` - 强制校验主机密钥
- `known-hosts: conf/known_hosts` - 使用默认路径

此时必须确保 `conf/known_hosts` 文件存在，且目标主机的公钥已录入该文件。

## 安装、升级与路径规则

### Windows

`install-agent.ps1` 首次复制源码目录中的 `conf\agent-config.yml`，重装时默认保留安装目录已有 YAML。
`run-installed-agent.ps1` 显式加载安装目录的配置，并把工作目录切换到安装目录。
因此配置中的 `known-hosts: conf/known_hosts` 指向 `<InstallRoot>\conf\known_hosts`，不是源码目录或 `System32`。

升级前先构建 JAR 并预检。以下命令显式选择修正后的源码模板；去掉 `-AgentConfigPath` 则预检并保留现场配置：

```powershell
Set-Location D:\King\sakura\sakura-execution-agent
mvn -B test package

.\scripts\install-agent.ps1 `
  -InstallRoot 'D:\King\sakura\sakura-admin\docker\sakura-execution-agent' `
  -AgentConfigPath '.\conf\agent-config.yml' `
  -Profiles mysql,oracle,postgresql `
  -KnownHostsPath '.\conf\known_hosts' `
  -Port 19091 `
  -PlanOnly
```

核对配置和安装计划后，在维护窗口去掉 `-PlanOnly` 执行正式安装，安装器会停止并重启目标 Agent。
`-AgentConfigPath` 表示替换整个 YAML，不做字段合并；现场存在自定义路径或授权项时应先备份并人工合并。
PowerShell 续行符是行尾反引号，后面不能跟空格；路径为 `known_hosts`，无需写成 `known\_hosts`。

为保留现有部署行为，安装入口仍用 JVM 参数固定 `127.0.0.1` 和指定端口；Windows 还固定使用
`<InstallRoot>\workspace\task-ledger.json`，避免升级后切换账本而丢失任务恢复状态。
其余已支持的 YAML 路径由 Java 统一解析，启动脚本不再强制要求默认 drivers/known_hosts/workspace 存在。
自定义目录需要部署者提前授予 `LOCAL SERVICE` 必要的读写权限；安装器只管理默认目录的权限。

### Linux 与 Docker

Linux 安装器支持 `--agent-config /path/to/agent-config.yml`，未指定时同样保留现场配置。
systemd 的工作目录为安装目录，启动参数显式传入该目录下的 `conf/agent-config.yml`。
默认共用的 `conf` 目录保持 `root:sakura 0750`（使用自定义服务组时替换 sakura），
YAML 和 known_hosts 为 `0640`，`agent.env` 保持 `root:root 0600`，由 systemd 读取后注入环境。
额外的工作目录、日志目录和授权目录需预先创建并赋予服务账号必要权限。

Docker 镜像内默认配置为 `/app/sakura-execution-agent/conf/agent-config.yml`。
Compose 挂载整个 `conf` 目录后会遮蔽镜像中的文件，宿主机挂载目录必须包含 YAML 和经过带外核对的 known_hosts。
默认 YAML 的相对路径适用于安装目录；`agent-config.production.yml` 中的 `/etc`、`/opt`、`/data` 等绝对路径
是 Linux 示例，使用前必须按实际节点或容器挂载路径调整，不能直接照搬到 Windows。

### 旧模板与预检边界

未知字段、重复键、显式空值、非法布尔值或多段 YAML 文档会被拒绝，不能靠静默忽略拼写错误改变安全配置。
旧模板的以下两项需按实际授权需求调整：

```yaml
local-action:
  workspace: workspace
  # workspace 自动授权；额外目录必须已存在，不能是磁盘根、用户主目录或符号链接。
  allow-roots: []
features:
  runtime-properties: {}
```

安装预检不创建目录、不读取 Token、不占用监听端口，也不连接 SSH 或数据库。
它只能证明 YAML 可解析且配置形状通过检查，不能证明某台 SSH 主机的公钥已被正确授权，
也不能替代服务账号权限检查；实际连接使用 `StrictHostKeyChecking=yes` 时，未知或变化的主机公钥仍会被拒绝。

## 日志输出

### 启用主机密钥校验时

```
SSH_KNOWN_HOSTS_VALIDATED taskId=xxx actionType=server_command file=/path/to/known_hosts strictHostKeyChecking=yes
```

### 跳过主机密钥校验时

```
SSH_HOST_KEY_CHECK_DISABLED taskId=xxx actionType=server_command host=192.168.1.100 strictHostKeyChecking=no reason=sakura.agent.ssh-skip-host-key-check=true
```

或对于 SFTP 上传：

```
SFTP_HOST_KEY_CHECK_DISABLED taskId=xxx actionType=server_file_upload host=192.168.1.100 strictHostKeyChecking=no reason=sakura.agent.ssh-skip-host-key-check=true
```

启动时也会在日志中记录配置状态：

```
AGENT_STARTED ... configFile=.../conf/agent-config.yml configLoaded=true sshSkipHostKeyCheck=false knownHosts=.../conf/known_hosts
```

## 安全建议

1. **生产环境必须启用主机密钥校验**（默认行为）
2. 跳过校验仅用于受控内网测试环境
3. 即使跳过主机密钥校验，账号密码仍需正确才能连接
4. 建议结合网络隔离、防火墙、VPN 等措施保证通道安全

## 示例

### 场景 1：开发测试环境，通过 YAML 配置跳过校验

**conf/agent-config.yml：**

```yaml
ssh:
  skip-host-key-check: true
```

**启动：**

```bash
java -jar sakura-execution-agent.jar
```

该配置仅关闭服务器身份校验，连接和身份认证仍需成功。

### 场景 2：生产环境，通过 YAML 配置强制校验

**conf/agent-config.yml：**

```yaml
ssh:
  skip-host-key-check: false
  known-hosts: /etc/sakura/known_hosts
```

**启动：**

```bash
java -jar sakura-execution-agent.jar
```

所有目标主机必须事先采集公钥、通过带外渠道核对指纹，再录入 known_hosts 文件。不要直接信任未核对的扫描结果。

### 场景 3：临时覆盖配置文件设置

假设 YAML 配置中 `skip-host-key-check: false`，但临时需要跳过校验：

```bash
java -Dsakura.agent.ssh-skip-host-key-check=true -jar sakura-execution-agent.jar
```

JVM 系统属性会覆盖 YAML 配置。

### 场景 4：使用自定义配置文件

```bash
java -Dsakura.agent.config=/data/sakura/custom-config.yml -jar sakura-execution-agent.jar
```
